## 1. Theme-by-theme inventory

### (a) Integer multiplication as digit convolution + carry propagation

**Has.**
- Decode is the lexicographic digit sum: `def decodeFinite (b : RadixSeq) (k : ℕ) (τ : FiniteRadixSpace b k) : ℕ := ∑ i : Fin (k + 1), (τ i : ℕ) * placeValue b i` (`FdrsFormal/Core/Finite/Bijection.lean:72`), with `digits_unique` (:192), `sum_div_mod_placeValue` (:96), `finiteRadixEquiv : FiniteRadixSpace b k ≃ Fin (placeValue b (k + 1))` (:447). Unbounded: `decode`/`encode`/`decode_encode`/`encode_decode`/`decode_injective` in `Core/Infinite/DirectLimit.lean:71,143,159,364,671`.
- Addition is transported, carries hidden inside `encode`: `noncomputable def add (b : RadixSeq) (τ σ : DirectLimitSpace b) : DirectLimitSpace b := encode b (decode b τ + decode b σ)` (`Operations/Addition/Correctness.lean`, Def 14), `add_decode_correct` (Prop 10), `carry_locality` (Prop 11, `Topology/Locality/Properties.lean:80`).
- The one explicit digit-vector carry on digits *beyond the radix* is application-specific: `def carryStep (d : ℕ → ℕ) (i : ℕ) : ℕ → ℕ := fun k => if k = i then d i % radix i else if k = i + 1 then d (i + 1) + d i / radix i else d k` with `carryStep_preserves_value` (Thm 113), `carryStep_digit_canonical`, `schedule_restores_bound` (Thm 115), `mul_accumulator_bound` (`Applications/Field25519Carry.lean:96-230`). The radix is hard-wired (`radix i = 2 ^ radixBits i`); `value d n := (Finset.range n).sum fun i => d i * 2 ^ weightBits i`.
- Convolutions: group convolution `cyclicMul (f g : G → ℂ)` on any finite abelian `G` (Thm 13, `NumberTheory/ArithmeticFunctions/CyclicConvolution.lean:58`); `cyclicConv` + `convolutionTheorem` on `ZMod N` (Thm 16, `Characters/AdditiveCharacters.lean:485,503`); `cyclic_conv` via two forward DFTs (Prop 161, below).

**Missing.** No multiplication operator on `𝓡` or `𝓡^{(k)}` anywhere (grep for `mul`/`multiplication` in `Operations/`, `Core/` is empty). No acyclic (linear) convolution as an object. No generic carry-normalization of `Fin (k+1) → ℕ` for an arbitrary `RadixSeq`. No Kronecker substitution, no polynomials over digit rings (the only `Polynomial` uses are `Modes/Adelic/FunctionFieldDegree.lean` and a growth-rate remark). No signed/balanced digits (grep empty in spec and Lean).

### (b) CRT address maps / multidimensional convolution

**Has.** `def crtChart (b : RadixSeq) (k n : ℕ) : FiniteRadixSpace b k := fun i => ⟨n % b i, _⟩`; `def ruritanian … := ∑ i, (σ i : ℕ) * coBlock b k i`; `def PairwiseCoprimeRadices (b : RadixSeq) (k : ℕ) : Prop := Pairwise fun i j : Fin (k + 1) => Nat.Coprime (b i) (b j)`; `theorem crtChart_bijective_iff (k : ℕ) : Function.Bijective (crtChartFin b k) ↔ PairwiseCoprimeRadices b k` (Thm 122); `ruritanianChart_bijective`; `dft_goodThomas` (Cor 33) — all `Characters/GoodThomas.lean:63-250`. Circuit-level: `exists_pfa_circuit … (hcop : Nat.Coprime n1 n2) … : ∃ C : Circuit (n1 * n2), C.Computes (fourierMatrix (n1 * n2)) ∧ C.size = n1 * C2.size + n2 * C1.size` (Thm 128) with the re-indexing lemma `sum_range_crt` (`CircuitCompose.lean:389,479`). Two-modulus CRT for projectors/characters: `residueProjector_CRT_factor`, `dirichletChar_CRT_factor` (Props 46–47, `Characters/CRT.lean`). Phase 13's `productRadix b₁ b₂` with `placeValue_product` (Thm 70) is a *digit-wise* product, and the spec explicitly warns "no truncated CRT" (fdrs.md ~8036).

**Partial / missing.** The CRT is only ever applied to the DFT, never to convolution: there is no statement "cyclic convolution of length N = ∏ aᵢ is t-dimensional convolution on ∏ ℤ/aᵢ", although `cyclicMul` is generic in `G` so it is a transport lemma away. The residue chart is a function, not an `AddEquiv`.

### (c) Bluestein, cyclic convolution via forward transforms, negacyclic twist, synthetic transforms

**Has** (`Characters/RaderBluestein.lean`): `theorem sum_zeta_pow_mul (n s : ℕ) (hn : n ≠ 0) : ∑ k ∈ Finset.range n, zeta n ^ (k * s) = if n ∣ s then (n : ℂ) else 0`; `theorem cyclic_conv (n : ℕ) (hn : n ≠ 0) (a b : ℕ → ℂ) (r : ℕ) (hr : r < n) : ∑ k ∈ range n, zeta n ^ ((n - r) % n * k) * ((∑ t, zeta n ^ (k * t) * b t) / n * ∑ q, zeta n ^ (k * q) * a q) = ∑ q ∈ range n, a q * b ((r + n - q) % n)` (Prop 161 — forward transforms only, mirrored index); the chirp identity `blu_phase … : zeta (2 * N) ^ (k * k) * (zeta (2 * N) ^ (q * q) * bluFilter N M ((k + M - q) % M)) = zeta N ^ (k * q)` with `bluFilter` placing `ζ_{2N}^{-t²}` at `t` and `M − t`; `exists_bluestein_circuit … (hM : 2 * N - 1 ≤ M) … : ∃ C' : Circuit N, … C'.size = 2 * C.size + M + 2 * chirpCount N` (Thm 130); `exists_rader_circuit` (Thm 129). Root-of-unity toolkit in `MixedRadixFFT.lean`: `zeta`, `zeta_pow_self`, `zeta_mul_pow_mul` (coarsening `ζ_{PQ}^{Qa} = ζ_P^a`), `zeta_isPrimitiveRoot`.

**Missing.** Nothing negacyclic: no `ℂ[y]/(y^r+1)`, no twist `w_j = ζ_{2r}^j` identity, no "root of unity as signed shift" (Nussbaumer); every transform is over `ℂ` scalars with `ζ` a genuine complex exponential. Bluestein's zero padding exists only inside the circuit construction (`bluU`), not as a linear-convolution lemma.

### (d) Lexicographic mixed-radix layouts, field interchange, shears, digit moves

**Has.** The address space is literally the layout: `def FiniteRadixSpace (b : RadixSeq) (k : ℕ) := (i : Fin (k + 1)) → Fin (b i)` with `decodeFinite` as the lexicographic address. Block products: `def blockProd (b : RadixSeq) (i j : ℕ) : ℕ := ∏ l ∈ Finset.Ico i j, b l`, `blockProd_mul`, `theorem placeValue_eq_mul_blockProd {i j : ℕ} (h : i ≤ j) : placeValue b j = placeValue b i * blockProd b i j` (`MixedRadixFFT.lean:93-113`). The only position permutation is full reversal: `revSeq`, `def revDigits (k : ℕ) (σ : FiniteRadixSpace b k) : FiniteRadixSpace (revSeq b k) k := fun l => ⟨σ (Fin.rev l), _⟩`, `reverseDecode_eq_decode`, `rdecEquiv` (Prop 157, `FFTCircuit.lean:68-118`). Splitting one bit off: `def lowEquiv (i : Fin (k + 1)) : Low k i × Fin 2 ≃ FiniteRadixSpace radixTwo k` (`FFTButterfly.lean:186`). Phase 13 `combine a b = a + b₁·b`, `projectA/projectB` (Prop 144) is a two-field pack/unpack at one position.
- `structure DigitPermutation (b : RadixSeq) (k : ℕ) where position : Fin (k + 1); perm : Equiv.Perm (Fin (b position))` with `digitPermutationAction`, `digitPermutation_isometry` (Def 37/Prop 34, `FunctionSpaces/LocalOperators/DigitPermutation.lean`) permutes *values within one digit*, not positions. Note: the Lean for Prop 35 is vacuous — `digitPermutation_commutation` concludes `f (digitPermutationAction b k dp τ) = f (digitPermutationAction b k dp τ)` by `rfl`. `Haar/WaveletPacket.lean:585-594` leaves "radix-permuted trees" as future work.

**Missing.** No swap of two digit fields, no `FiniteRadixSpace b k ≃ FiniteRadixSpace (b ∘ π) k`, no shear `(H, D) ↦ (H + D, D)` on a residue ring, no digit-move formula `dec(τ') − dec(τ)`.

### (e) Simultaneous butterfly layers on selected bits

**Has.** `def bfGates (W : ℂ) (a0 a1 pos : ℕ) : List LGate := [.scale W a1, .add a0 pos, .sub a0 pos]` with `bfGates_spec`, `bfRow` (`FFTButterfly.lean:49-110`); `stage_radixTwo` (Prop 159: `(T_i y)(ρ) = y(ρ⁰) + (−1)^{ρ_i} W_i(ρ⁰) y(ρ¹)`); `exists_butterfly_circuit` (Thm 124, `3·2^k·(k+1)` gates); trivial-twiddle skipping (Thm 125, `FFTTwiddleSkip.lean`); the conjugate-pair layer `s_j = x_j + x_{n−j}, d_j = x_j − x_{n−j}` (Thm 126, `PairKernel.lean`). `vilenkinKernel k τ σ := ∏ i, zeta (b i) ^ ((τ i : ℕ) * σ i)` on `radixTwo` is the Walsh–Hadamard kernel (never named as such; grep `Walsh|Hadamard` is empty).

**Missing.** The normalized `H0(u,v) = ((u+v)/2, (u−v)/2)` as an involutive change of basis on a *set* of bits, and the tensor-product reading (layer on `S` = `⊗_{i∈S} H0`). In Definition 216 the `/2` is a charged `scale` gate.

### (f) Cost recursions with a power saving

**Has.** Exact gate-count recursions: `def Plan.cost : Plan → ℕ | .two => 2 | .pair h => (2*h+1)^2 - 1 | .ct p q => p.len * q.cost + q.len * p.cost + twiddleCount p.len q.len | .pfa p q => p.len * q.cost + q.len * p.cost` and `XPlan.cost` (Rader `2C + 2n + 1`, Bluestein `2C + M + 2·chirpCount`), each proven sound (`Plan.exists_circuit`, `XPlan.exists_circuit`) and kernel-evaluated for `N ≤ 512` (`SearchCertificates*.lean`, `decide +kernel`). Asymptotic statements: `MainStatement` (recorded, unproven), `mainStatement_of_three_halves_lt` (Cor 35), Cor 36's `3/2 − (N−1)/(N log₂ N)`. Read-count measure `ReadsAtMost` (Prop 156). Separate, older cost vocabulary: `touchComplexity`, `circuitDepth`, `tick_expected_complexity` (`Integration/Complexity/Definition.lean`). The Rust planner (`tools/radix-circuit-search`) is a dynamic program over these recursions.

**Missing.** No recurrence *solving* (no master-theorem lemma), no notion of "a parameter × m costs s/W < m as much", and — the structural mismatch — Definition 216 charges one unit per exact `ℂ` gate regardless of precision, while family 109's cost is bit complexity. There is no product gate: `inductive Gate (w : ℕ) | add (i j) | sub (i j) | scale (c : ℂ) (i)` (`FourierCircuit.lean:53`), so no bilinear map is expressible as a circuit today.

## 2. Specific checks

**B_i·B_j = B_{i+j}; constant schedules.** Not present. What exists: `placeValue.succ : placeValue b (m + 1) = placeValue b m * b m`, `placeValue_eq_mul_blockProd` (`B_j = B_i·B_{[i,j)}`), `placeValue_product` (digit-wise product radix), `placeValue_binary` (`Modes/SyntheticPlace/Dimension.lean`, `placeValue radixTwo m = 2^m`) and an inline copy in `FFTCircuit.lean:291`; `overflowRatio_constant` builds a constant schedule ad hoc as `⟨fun _ => a, fun _ => ha⟩` and proves `placeValue = a^L` by local induction (`Integration/ThreeLineMediator/Definition.lean:372`). There is no `RadixSeq.const`, no `IsConstant`, and no characterization theorem; `RadixLaw.isPositionOnly` (`Modes/VariableRadix/Basic/RadixLaw.lean:93`) is path-independence, not constancy.

**Carry/normalization for digits beyond the radix.** Only `Field25519Carry.lean` (quoted in (a)), with a fixed radix law and numeric bounds. The generic odometer (`Modes/VariableRadix/VariableTick/CarryAlgorithm.lean`: `carryIndex`, `tickByCarry`, `carry_preserves_prefix`, `carry_increments`, `carry_resets_suffix`) handles `+1` on canonical digits only. `encodeFinite`/`encode` normalize a *value* by div/mod; there is no sweep from `(i : Fin (k+1)) → ℕ` to `FiniteRadixSpace b k` for general `b`. Phase 12's `UnitCarry.lean` (`fitCount`, `overflowCarry`) is real-valued and unrelated. The interface-balance ledger (Thm 89, `SyntheticPlace/InterfaceBalance.lean`: `Balanced`, `reachable_balanced`, `reachable_consumed_le_issued`) is the abstract "issued = consumed + pending" that Thm 113 instantiates.

**Digit-permutation / field-swap equivalences of `FiniteRadixSpace`.** `digitPermutation_isometry : Function.Bijective (digitPermutationAction b k dp)` (within-digit), `rdecEquiv` / `revDigits` (full reversal, with a schedule change to `revSeq`), `lowEquiv` (one bit), `finiteRadixEquiv`. No two-position swap; no `Equiv.Perm (Fin (k+1))` action (grep for `Fin.rev` outside FFTCircuit and `Equiv.Perm (Fin (k + 1))` is empty).

## 3. Candidate items for a new addendum

Numbering continues the global ids (next free: Definition 218, Proposition 162, Theorem 131, Corollary 39; Lemma 6 is also free). Notation: `B_i = placeValue b i`, `dec_k`, `𝓡^{(k)}`, `B_{[i,j)} = blockProd b i j`, `ζ_n = zeta n`.

1. **Definition 218 (constant schedule; digit convolution; the carry sweep).** `IsConstant b := ∀ i, b i = b 0` (and `RadixSeq.const q (hq : 2 ≤ q)`). For `x y : ℕ → ℕ` supported below `k+1`, `(x ⋆ y) m := ∑ i ∈ range (m+1), x i * y (m − i)`. For a general `b`, `carryStep b d i` as in Field25519 with `radix i := b i`, and `sweep b d n := ` the fold of `carryStep` over `i < n`. Value `val b d n := ∑ i ∈ range n, d i * placeValue b i`. Uses: `Field25519Carry.carryStep` as the template. **S.**

2. **Proposition 162 (B_i B_j = B_{i+j} iff the schedule is constant).** `(∀ i j, placeValue b i * placeValue b j = placeValue b (i + j)) ↔ ∀ i, b i = b 0`. ⇐: `placeValue b m = (b 0)^m` by induction on `placeValue.succ`; ⇒: at `i = 1`, `B_1 B_j = B_{j+1} = B_j · b_j`, cancel `B_j ≠ 0` (`placeValue.ne_zero`, `Nat.eq_of_mul_eq_mul_left`). Companion: always `B_{i+j} = B_i · B_{[i,i+j)}` (`placeValue_eq_mul_blockProd`), so constancy is exactly shift-invariance `B_{[i,i+j)} = B_j`. **S.**

3. **Theorem 131 (digit convolution plus carries is the integer product, constant radix).** For `IsConstant b`, `x y : 𝓡^{(k)}`: `val b (x ⋆ y) (2k+1) = dec_k x * dec_k y`, hence `sweep b (x ⋆ y) (2k+1)` is a canonical digit vector with `val … = dec_k x * dec_k y`, i.e. `enc_{2k+1}(dec x · dec y) = sweep (x ⋆ y)`. Proof: expand `(∑ x_i B_i)(∑ y_j B_j)`, regroup by `m = i + j` using Prop 162; carries by iterating `carryStep_preserves_value` (generalized) and `digits_unique`. **M** (the regrouping sum lemma is the only real work; `Finset.sum_mul_sum` + `Finset.sum_sigma`/`Nat.antidiagonal`).

4. **Corollary 39 (the variable-radix boundary).** For `k ≥ 1`, `∀ x y : 𝓡^{(k)}, val b (x ⋆ y) = dec x · dec y` **iff** `b` is constant on `0..2k` (unit vectors `e_i, e_j` reduce to Prop 162; counterexample `b = (2,3,…)`: `B_1 B_1 = 4 ≠ B_2 = 6`). This is the multiplicative twin of Prop 154 ("the twist is the carry"): on a non-constant schedule, multiplication is *not* a convolution in the digit chart. **S.**

5. **Definition 219 (the bilinear gate model).** Extend `Gate`/`LGate` with `mul (i j)`; a bilinear circuit on inputs `(x, y)` with `Computes` against a bilinear map. Requires touching `Program.eval`, `exec`, `Circuit.ofGates`, `reloc`/`Gate.reloc` (CircuitCompose). **L** (mechanical but wide: every `_spec` lemma over `LGate` gains a case).

6. **Theorem 132 (an exact convolution circuit).** For `n ≥ 1`, `M ≥ 2n − 1`, and any exact Fourier circuit `C` of length `M` (Cor 38 supplies one for every `M ≤ 512` and the grammar for all `M`), the acyclic convolution of two length-`n` inputs is computed by a bilinear circuit with `3|C| + M` gates: two forward DFTs of the zero-padded inputs, `M` product gates, one forward DFT read at `(M − r) mod M` (`cyclic_conv` with both `a, b` variable; `conv_select` unchanged). Corollary: with Thm 131, `k+1`-digit constant-radix integers multiply exactly in `3|C_M| + M` ℂ-gates plus a carry sweep *outside the model*. Honest scope: unit-cost exact `ℂ` gates, not bit complexity; family 109's `O(n log n · 4^{log* n})`-type claims are to be recorded, not proven (as `MainStatement` is). **L** (depends on 5).

7. **Definition 220 / Proposition 163 (field interchange as three shears).** For positions `i ≠ j` with `h : b i = b j =: q`, define the shear `sh_{i←j} τ := τ[i := τ_i + τ_j mod q]` and the position swap `swap_{ij} : 𝓡^{(k)} ≃ 𝓡^{(k)}`. Then `swap_{ij} = S_{j,neg} ∘ sh_{i←j} ∘ sh_{j←i}^{-1} ∘ sh_{i←j}` (the classical `(u,v) ↦ (u+v, v) ↦ (u+v, −u) ↦ (v, −u)`, finished by Def 37's within-digit negation), and the digit-move formula `dec (swap_{ij} τ) = dec τ + (τ_j − τ_i)(B_i − B_j)` (over `ℤ`). Uses `DigitPermutation` (cast style `h ▸` as in `digitPermutationAction`), `Function.update`, `decodeFinite`. Also repairs the vacuous Prop 35 if the commutation with `P_L` is restated for swaps. **M** (dependent-type plumbing around `Fin (b i)` vs `Fin (b j)`; consider stating on `Fin q × Fin q` via `lowEquiv`-style splitting first).

8. **Proposition 164 (the negacyclic twist).** For `r ≥ 1`, `w_j := ζ_{2r}^j`, `a b : ℕ → ℂ`: `negacyc r a b m := ∑ q ∈ range r, if q ≤ m then a q * b (m − q) else −(a q * b (m + r − q))` satisfies `negacyc r a b m = w_m⁻¹ · cyc_r (w·a) (w·b) m`, where `cyc_r` is the cyclic sum of Prop 161's right-hand side. Proof: `w_q w_{(m−q) mod r} = w_m · (−1)^{[q > m]}` from `zeta_pow_self (2r)` giving `ζ_{2r}^r = −1` (`zeta_mul_pow_mul` for the coarsening). Corollary 40: negacyclic convolution costs cyclic plus `2r` scales and `r` unscales in the model of Def 219 (reads off `cyclic_conv`). Stay with sequences on `ℕ → ℂ` as RaderBluestein does; the ring form `ℂ[y]/(y^r+1)` via `AdjoinRoot` is a separate **L** item and not needed for the identity. **S–M.**

9. **Proposition 165 (the residue chart carries convolution).** Under `PairwiseCoprimeRadices b k`, the CRT chart is an `AddEquiv ZMod (placeValue b (k+1)) ≃+ ∀ i, ZMod (b i)` and `cyclicMul` transports: `cyclicMul (f ∘ e.symm) (g ∘ e.symm) = cyclicMul f g ∘ e.symm` — cyclic convolution of length `N` *is* the `(k+1)`-dimensional convolution on the Vilenkin group. First half uses `crtChart_bijective_iff` (or Mathlib's `ZMod.prodEquivPi` if present at the pinned revision; otherwise iterate `ZMod.chineseRemainder`); second half is a one-line `Fintype.sum_equiv`, the technique already used in `CyclicConvolution.lean`. Reading: theme (b) is the convolution twin of Cor 33. **M.**

10. **Proposition 166 (the simultaneous butterfly layer).** On `radixTwo`, for a set `S` of positions, `H_S := ⊗_{i∈S} ½[[1,1],[1,−1]]` acting through `lowEquiv`; `H_S ∘ H_S = id`, and `H_{all}` is `2^{-(k+1)} · vilenkinKernel` (Walsh–Hadamard). Gate cost in Def 216: `2` per pair unnormalized, `4` with the charged `½`. Uses `vilenkinKernel`, `zeta_two`, `lowEquiv`, `bfGates_spec`. **M.**

11. **Corollary 41 (the constant-radix split recursion, optional).** For `b ≡ q`, `Plan.cost` of the balanced positional tree satisfies `C(q^{m}) = q·C(q^{m−1}) + q^{m−1}·C(q) + twiddleCount q q^{m−1}`; solving recovers `≤ N·(2q−1)·m` (Thm 123) — a sanity bridge, not new mathematics. **S.** Anything resembling family 109's `s/W < m` saving has no counterpart and should be recorded, not claimed.
